1. 資料來源與讀法

  • 程式核對 portfolio-tracker-v15.html、server.py、sw.js、data/update_fund.py、四個 GitHub Actions、STORAGE_KEYS、_buildLocalUserPayload、calculateStats。

讀法。 Notion 各頁是當下那一輪的紀錄。損益頁、資料流程頁在 2026-07-13 當時確認正式線是 v15.941；優化清單停在 2026-04-30 也是當時進度。 程式之後續編到 v15.949。以下現況以程式為準；第 11 章對照「當時寫什麼、後來哪一版改到現在」。

2. 專案定位

個人用的台／美／港股持倉追蹤器。沒有帳號系統、沒有伺服器端使用者資料庫。 瀏覽器打開就能用，也能以 PWA 裝到 Android 主畫面。

單一 HTML所有 UI 與業務邏輯都在 v15 這一個檔。v13 / v14 只留著備用。
個人工具目標使用者就是作者本人。跨裝置靠 Gist，不是多租戶 SaaS。

Notion 主頁 2026-04 寫的目標仍成立：「跨裝置的股票投資組合追蹤」。 之後陸續加上貸款、存款、公司行動、觀察清單 Pro、投資日損益、system sync，主頁摘要還沒補到這些後來的版本。

6. 損益模型

v15.082 當時今日損益只採計 open；v15.902 當時 close pair 是每檔一筆 pt_close_pair_v1。 這兩段寫在 Notion 損益頁舊章節裡，是當時的契約。 v15.907 起改投資日模型（open + closed_retained），cache 升 pt_close_pair_v3，並維持至今。 現行計算在 calculateStats。

投資日

_portfolioDay 以台北時間 08:00 換日。08:00 前仍算前一個投資日。 三市場的交易時段都不跨這個點，所以換日是乾淨的一整批切換。

今日損益

盤中 open：
  (currentPrice − 前一交易日 exact final pair.close) × 股數

已收盤 closed_retained：
  final pair(投資日).close − pair.prevClose
  凍結到隔日 08:00

不計入：not_open、closed_or_holiday

採計函式是 _eligibleTodayStatus = open || closed_retained。 盤中不接受「用今日 pair 的 prevClose 湊合」。基準還沒驗證就顯示「基準資料校驗中」（v15.944），避免颱風假誤標後把兩日漲幅加在一起。 任一採計市場資料不齊，總額顯示「資料不足」，不做部分合計。

前次收盤損益

只讀投資日前一交易日的 exact final pair：pair.close − pair.prevClose。 不再讀 CSV dayChange、h.prevClose、snapshot、baseline。

合法 close pair

_isExactFinalClosePair 必須同時成立：

  • final === true
  • targetDate 就是要算的那天
  • prevDate 等於該市場的前一交易日（禁止跳更早的交易日）
  • 兩邊 close 都 > 0

來源優先：fundamentals.json.recent_closes → 本機／Gist cache → Yahoo chart 10d。 分割後會把歷史 close 轉成目前持倉尺度再算（v15.921）。

行事曆：TW／HK 只精確到 2026；US 已補 2027（v15.925）。 未涵蓋年份降級為週末判斷，缺資料就顯示不足，不會跳日硬算。

7. 同步與備份

Gist：user push

  • 改使用者資料 → _markAndAutoPush → 2 秒 debounce 靜默推。
  • 先比 userDataHash。相同就 noop，不 PATCH。
  • 手動推送三選一：標記最新版（master）／暫存上傳／取消。只有 master 寫 userConfirmedCloudMaster。
  • 401／403 立刻停 retry，toast 提示 Token 失效。
  • 「⚠ N 筆未同步」只數 user domains，快照不算。

Gist：system push

收盤快照與 close pair 走 _scheduleSystemSyncPush。 開頭有 _isApplyingCloudPull guard，避免 pull 期間又排 push。

FSA 本機資料夾

_isFsaSupported 三層擋：必須有 showDirectoryPicker、安全上下文、IndexedDB； Android／iPhone／iPad／Mobile UA 一律 false。與 Gist 互斥。

備份層級

  1. localStorage（裝置）
  2. Gist（跨裝置，有 revision）
  3. Actions 每日把 Gist 寫進 data/portfolio_backup.db
  4. CSV 匯出（離線保底，含 Lots / TradeHistory / Loans）

還原工具：data/restore_from_sqlite.py。

8. 報價與外部資料

盤中現價

一鍵更新／每分鐘靜默 → Google Sheet CSV → CORS proxy 鏈 → _lookupPrice → _acceptIncomingPriceForHolding（拒收分割前舊價）→ holdings.currentPrice。

Proxy 順序：allorigins → codetabs → corsproxy；本機或已設後端時再加 /fetch-sheet。上次成功的節點會記在 pt_sheet_proxy_idx_v1。

_lookupPrice 台股允許 00675L ↔ 00675L.TW； v15.949 起港股同樣允許 9747 ↔ 9747.HK。

港股免費源延遲約 15–20 分。v15.942 只在今日損益卡底部加註腳，沒改來源。 Google Sheet「發布到網路」本身還有 5–10 分鐘伺服器快取，程式控制不了。

基本面

Actions 跑 update_fund.py，寫 data/fundamentals.json。 早期排程與腳本檔頭寫「每 6 小時」；後來 update-fundamentals.yml 改成每天 UTC 00/12 兩次（台灣 08:00／20:00），並維持至今。 財報日可用 EARNINGS_PROXY 對槓桿／港股反推原型，但 mapping 只影響財報日期，不改 PE／技術面。

前端快取失敗時應設 null 而不是 {}（v15.042）。新鮮度用灰／橘／紅顯示。

9. 貸款、公司行動、觀察清單

貸款

v15.918 起餘額只由「原始本金 + 固定月付 + 首次還款日」即時推導。 _processAllLoansAutoDebit 是空函式。日期變化不寫資料、不產生 pending。

INV-2 仍有效：貸款不進五張統計卡、不進圓餅、不改總投入／總市值／今日損益。

v15.949 補上跨貸款的「每月應還」： 本期應付 = nextInterest + nextPrincipal（最後一期自動小於月付）； 月付過低或還沒高過利息的不計入。持倉總資產列可顯示「月還」，點了進 Tab 8，不從總資產扣除。

公司行動

正向分割：價格尺度偵測 + Yahoo official split 核對後可自動套用。 反向分割／減資：即使官方核對成功也不自動套用（畸零股折現、現金減資退款，總成本不該守恆）。 套用前硬檢查總成本守恆；FIFO 逐批 qty×ratio / cost÷ratio。

觀察清單

與持倉報價、close pair、損益完全獨立。漲跌算錯不代表持倉損益錯。 Pro 圖有 TradingView widget（公開版最多約 5 個 study）與原生圖 fallback。 v15.926–v15.947 已經很厚，不該再當預設擴充區。

12. 現況結論

這是一個把「個人財務儀表板」和「跨裝置同步協議」塞進同一個 HTML 的成熟工具。 難的地方不在畫表格，而在：報價延遲、行事曆缺口、分割尺度、以及「系統算出來的數字不能被當成使用者改了資料」。

  • 損益公式從 v15.907／v15.923／v15.944 這幾輪之後已經收斂。現在比較容易出狀況的是資料還沒到，或行事曆／分割把基準日弄歪。
  • 同步協議以 v15.079 hash-first 為準。較早的時間戳比較、revision-only 規則已寫在「已失效規則總覽」，讀舊節時要看它被哪一版取代。
  • 產品上最擠的是持倉頁；觀察清單從 v15.926 起已經很厚，不適合當預設擴充區。
  • 單檔約 1 MB 是維護成本，但 Pages／PWA／版本比對都綁在這一個檔。沒有明確重構需求前，維持單檔比較安全。

下一步怎麼排，見 未來優化報告。
