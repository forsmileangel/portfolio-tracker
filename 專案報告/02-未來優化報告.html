3.2 文件補寫現行行為（不改程式）

舊段落請留著作歷程。若要讓之後讀文件的人一次對到現況，可以在既有紀錄上面加一則現行補記，不要整段刪掉當時的文字：

  • README：在「不會跨裝置同步」旁邊或上方補「v15.4 起已有 Gist，並維持至今」；版本表可加石墨／九個 Tab。
  • Notion 損益頁：保留 v15.082／v15.902 舊節，頂部補記現行是投資日 + pt_close_pair_v3（v15.907 起）。
  • 資料流程頁：保留 2026-07-13「當時正式線 v15.941」補記；另加一則現行已到 v15.949、基本面每天兩次。
  • update_fund.py 檔頭註解可改成與 workflow 相同的每天兩次，不影響執行。
  • frontend-design 技能：註明 v15.1 藍黑、v15.943 起石墨。之後做 UI 才不會沿用舊色票。

3.3 持倉頁拆出設定／診斷

匯率、Sheet URL、Gist、FSA、錯誤日誌、公司行動入口全擠在 Tab 1。 每天看損益的視線會被設定區打斷。這是 UX 債，不是功能債。

做法：新增「設定」Tab 或把現有區塊折疊成預設收合。不改任何儲存 key 與同步。

3.4 港股盤中現價（可選）

v15.942 已記錄備選案：港股改 Yahoo 直抓現價，帶真實時間戳。 仍會延遲約 15 分，但比 Sheet 開盤後卡前日收盤誠實。 只動 currentPrice 來源，不動 close pair。 要另開一版仔細做，不要跟文件整理綁在一起。

3.5 開發用 Gist 隔離

localhost 若共用正式 Gist，本機實驗持倉有機會推進去。 小改：hostname 是 localhost 時改讀另一組 dev Gist ID，或直接禁止靜默 push。

3.6 進版三處版本號的 CI

一個 workflow：抓 HTML 裡 changelog 首行、APP_VERSION、左上角字串，三者必須相同。 這是 PWA 更新能動的硬條件，適合自動化。

5. 排程、先別跟功能綁在一起

  • 已實現損益表改 DOM diff： renderRealizedTab 仍整塊 innerHTML。觸發頻率低、預設不在前景，優先度低。
  • 容量自動搬遷： v15.944 已能警告 > 4 MiB，close pair 也已修剪 30 日。 「自動把 90 天快照搬上 Gist 再刪本機」會碰到 system push 規則，不要當小修。
  • 更多 #region：對人翻 1 萬行有幫助，對行為零影響。可順手做，不必專開一版。

已改走別條路、但仍要留著的相容層

有些做法後來被取代，但程式裡還留著呼叫點或讀舊資料的路徑。 沒有找到可以確定完全用不到、刪了也不影響功能的程式。 因此這份報告不建議移除下列項目：

  • _processAllLoansAutoDebit：v15.918 起改為空函式，但 pull／啟動路徑仍會呼叫，是刻意留下的相容入口。
  • pt_close_pair_v2 讀取合併：v3 上線後仍用來接舊裝置 cache，不是死碼。
  • STORAGE_KEYS.cashLegacy：老使用者 localStorage 可能還有這個 key。
  • sw.js no-op：v15.024 起不再快取 API，但安裝／activate 仍要清舊 cache、接管 PWA，不能刪檔。
  • v13／v14 HTML、Notion 裡 2026-07-13「當時正式線 v15.941」補記：都是歷程，留著。

6. 架構級：拆檔與 v16

Notion 未來設計頁推薦下一次重寫用 Vite + TypeScript。 以目前 1 MB／14,607 行來看，這個判斷「長期正確」。 以 v15.900 之後的實際路徑來看，現在做會比問題本身危險。

  • PWA 版本比對、GitHub Pages、單檔離線開啟，都假設入口是這一個 HTML。
  • 拆 CSS／JS 之後，快取策略、SRI、SW、相對路徑都要重測三平台。
  • v15.900 曾宣告凍結，後來證明小步 hotfix 比大重寫安全。
建議：沒有「明確要重構、並接受一段時間只修架構不修功能」的指令前，不要拆檔、不要開 v16。 若真的要做，先把文件與 CI 版本檢查做好，當安全網，再抽 CSS（最小），最後才動 JS 模組。

7. 明確不要做

念頭為什麼不要
把貸款扣進總資產或圓餅 破壞「總市值＝持股市值」的閱讀習慣，違反 v15.917 INV-2。
恢復每月自動寫還款流水帳 v15.918 拿掉就是為了避免日期一變就製造 Gist pending。
再堆觀察清單指標 TradingView 公開 widget 大約只能穩載 5 個 study（v15.947 已為此砍過）。
買 HKEX 即時 feed 授權費與個人工具不成比例。誠實標示延遲即可。
讓 Service Worker 快取 fundamentals / Gist / CSV v15.024 的回歸：使用者會看到舊報價、舊雲端。
用 calendar date 當 marketDate、或 close=null 就跳日 兩倍漲幅／颱風假系列的根。規則已寫死。
猜 2027 台港假日 猜錯比「資料不足」更糟。

8. 建議順序

假設每次只做一小段、而且要能單獨進版：

  1. 文件對齊：README + Notion 損益／資料流程標題 + 腳本註解。零行為風險。
  2. 進版 CI：三處版本號一致性檢查。
  3. 持倉頁設定區收合或外移：只動 DOM 分組。
  4. dev Gist 隔離：保護正式雲端。
  5. TW／HK 2027 行事曆：等公告。
  6. 港股 Yahoo 現價：有明確體感需求再做。
  7. 核心函式 JSDoc：當拆檔的前置，不是獨立產品功能。
  8. 拆檔／v16：單獨專案期，不要夾帶功能。
使用者規則仍是「不主動加功能，等指定再做」。 這份報告只排序可能性，不代表下一版要開工。
